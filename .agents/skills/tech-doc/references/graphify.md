# Graphify и хранение документации в Git

Читай при использовании графа для документации или настройке хранения его результатов.

## Размещение и навигация

Корневой README ссылается на `graphify-out/README.md`. Этот ручной документ содержит
статус графа, ссылки на существующие результаты и правила работы с ними; он остаётся
полезным, даже если граф ещё не построен. При появлении артефактов добавь ссылки
на них и сведения о срезе, а не выдумывай результаты анализа.

README модулей в `service/{name}/` могут ссылаться на общий граф. Отдельные графы
модулей не создаются автоматически. Существенные проверенные выводы сохраняй
в `service/{name}/docs/` или общих `docs/` с навигацией из соответствующего README.

## Работа с графом

1. Используй доступный скилл `graphify` для построения, обновления и запросов.
   Если инструмент недоступен, укажи ограничение и исследуй исходники непосредственно.
2. Перед выводами проверь соответствие графа текущим исходникам и конфигурации. Устаревший граф сначала
   обнови в рамках разрешённой области; если обновление недоступно, явно сообщи ограничение
   и проверяй утверждения непосредственно по коду.
3. Исключи исторические handoff из корпуса. При обновлении убери извлечённые из них узлы и связи,
   учитывая их происхождение и сохраняя сведения с независимыми актуальными доказательствами.
   Исходные handoff-файлы не удаляй. Если исключения не настроены, не используй такие узлы как доказательства.
4. Проверяй найденные существенные связи по исходникам, DI, конфигурации и тестам.
   При необходимости изучай установленный общий пакет: его реализация может отсутствовать в графе.
5. Переноси проверенные выводы в README, архитектурный сценарий или описание интеграции по правилам скилла.
    Автоматический `GRAPH_REPORT.md` оставляй перегенерируемым; ручные исследования храни отдельно.

В корпус включай код `service/`, конфигурацию и релевантную поддерживаемую документацию.
Общие пакеты включай, когда они появятся. Исключай `.git/`, `.agents/`, бинарники,
кеши, секреты, исторические handoff и сгенерированные результаты Graphify, чтобы
не анализировать библиотеку навыков и собственные автоматические отчёты как код сервиса.
Фиксируй фактический состав и исключения при построении.

В исследовательском документе указывай срез кода и ограничения извлечения: направление рёбер,
неразрешённые ссылки, схлопывание связей, непроанализированные зависимости.
Отсутствие связи в графе не доказывает её отсутствия в реализации.
Объединение связанных узлов в кластер не доказывает наличие бизнес-модуля.

## Что хранить в Git

| Материал | Политика |
| --- | --- |
| README и поддерживаемая документация в `docs/` и `service/{name}/docs/` | Хранить как проверенное описание системы |
| `graphify-out/README.md` | Хранить как ручную навигацию и правила работы с графом |
| Команды Makefile и настройки исключений Graphify | Хранить для повторного построения |
| `graphify-out/graph.json` | Хранить как вспомогательный снимок карты проекта |
| `graphify-out/GRAPH_REPORT.md` | Хранить как автоматическую сводку снимка |
| Подписи групп и необходимые метаданные | Хранить для интерпретации снимка |
| `graphify-out/graph.html` | Исключать: генерируется из графа |
| Кеш, временные файлы и история запросов агентов | Исключать как локальные рабочие данные |

У сохраняемого снимка фиксируй версию Graphify и срез анализируемого кода:
commit, дату и наличие незакоммиченных изменений. Используй существующие метаданные инструмента,
а недостающее добавляй в небольшой сопроводительный файл. Проверяй, что сохраняемые артефакты
не содержат секретов, персональных данных и абсолютных локальных путей.

Обновляй снимок вместе с изменениями модулей, контрактов и взаимодействий; косметические изменения
не требуют обязательного перестроения. Граф не заменяет документацию и не должен быть необходим
для её чтения. Эти правила хранения не являются разрешением на создание коммита,
массовую миграцию файлов или изменение настроек вне запрошенной области.
