# Пакет `fileinbox`

`fileinbox` принимает файловые публикации из одного каталога Linux и
последовательно передаёт их обработчику модуля. Пакет отвечает за сканирование,
чтение с лимитом, повторы и удаление. Разбор содержимого, проверка события и
постановка в очередь остаются за модулем.

## Подключение

Выделите отдельный каталог для каждого модуля и запускайте только один приёмник
на каталог. Передайте в [`bootstrap.New`](bootstrap/app.go) настройки,
обработчик, логгер и часы. Конструктор проверяет настройки, не открывая каталог и
не запуская фоновые задачи. Ниже — пример значений, а не умолчания пакета.

```go
package bootstrap

import (
    "log/slog"
    "time"

    pkgClock "github.com/vendelev/sre-metrics/pkg/clock"
    pkgFileInboxApi "github.com/vendelev/sre-metrics/pkg/fileinbox/api"
    pkgFileInboxBootstrap "github.com/vendelev/sre-metrics/pkg/fileinbox/bootstrap"
    pkgFileInboxConfig "github.com/vendelev/sre-metrics/pkg/fileinbox/config"
)

func newFileInbox(dir string, handle pkgFileInboxApi.Handle, logger *slog.Logger) (pkgFileInboxApi.Inbox, error) {
    return pkgFileInboxBootstrap.New(pkgFileInboxConfig.Config{
        Dir:             dir,
        ScanInterval:    time.Second,
        MaxFilesPerScan: 256,
        MaxFileBytes:    16 * 1024,
        MaxAttempts:     3,
    }, handle, logger, pkgClock.RealTime{})
}
```

[`Handle`](api/inbox.go) получает байты публикации и время текущей попытки.
Возвращайте `nil` только после успешного приёма, `api.ErrRetry` при временной
невозможности принять файл (например, очередь полна), другую ошибку при
окончательном отказе. `ErrRetry` оставляет файл для следующего скана и не расходует
лимит файловых ошибок. Обработчик не должен блокироваться.

## Запуск и остановка

1. Если нужны метрики, до запуска вызовите `ActivateMetrics` с `meter` сервиса.
   Пакет регистрирует инструменты, но не создаёт и не останавливает экспорт.
2. Запустите `Run` один раз в фоновой задаче сервиса. При запуске ждите
   `Ready`, завершение `Run` или отмену. `Ready` означает, что каталог удалось
   прочитать, а не что первая пачка обработана. После готовности продолжайте
   следить за результатом `Run`.
3. При остановке вызовите `Stop` и дождитесь завершения `Run` в пределах бюджета
   сервиса. `Stop` не прерывает начатый `Handle` и не закрывает очередь модуля.

## Публикация и гарантии

Отправитель атомарно переименовывает готовый временный файл в `<uuid>.json` в том
же каталоге. После публикации файл нельзя изменять или заменять. Уведомления
ускоряют обработку, но источником истины остаётся периодический скан.

Исчезновение файла не подтверждает успешный приём: при окончательном отказе файл
тоже удаляется. Состояние попыток не сохраняется между запусками; получатель
может повторно передать публикацию, если процесс остановился до удаления.
Подробнее — в [контракте пакета](api/doc.go) и в [описании интеграции
`user-login`](../../../docs/file-inbox.md), где приведены требования к
отправителю, ограничения общего тома и диагностические метрики.
