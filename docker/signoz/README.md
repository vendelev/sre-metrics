# Локальный SigNoz для сравнения с Grafana

Стенд подключается через `include: docker-compose.signoz.yml` в основном
[docker-compose.yml](../../docker-compose.yml). Дополнительный override не требуется.
ClickHouse SigNoz отделён от хранилищ внешних приложений.

Используются закреплённые версии SigNoz `v0.148.1`, его Collector `v0.144.15`
и ClickHouse `25.12.5`. За основу взяты актуальные конфиги официального
[SigNoz Foundry](https://github.com/SigNoz/foundry/tree/main/docs/examples/docker/compose),
с адаптацией под небольшой однопользовательский dev-стенд:

- один отдельный ClickHouse с встроенным Keeper вместо отдельного ZooKeeper;
- SQLite для пользователей и настроек интерфейса вместо отдельного PostgreSQL;
- один SigNoz Collector, принимающий только OTLP-трейсы и метрики;
- без hostmetrics, Docker socket, сбора логов, управления Collector через OpAMP
  и внешней аналитики;
- небольшие батчи и очереди, ограниченные CPU, память, параллелизм и кеши;
- отдельные тома `signoz_clickhouse_data`, `signoz_data`, `signoz_scripts`.

SigNoz Collector необходим: обычный OTLP-экспортёр нашего Collector не записывает
данные напрямую в специфичную схему ClickHouse SigNoz. Помимо записи трейсов,
он генерирует собственные метрики `signozspanmetrics/delta` для APM-интерфейса
SigNoz. Это отдельные производные метрики, а не изменение исходных трейсов.
Экспортёр `metadataexporter` сохраняет метаданные для фильтров и поиска в интерфейсе.

## Запуск

```sh
docker compose up -d signoz signoz-collector
docker compose up -d --build
```

Зависимости запускаются автоматически. `signoz-init` один раз загружает
официальную UDF `histogramQuantile` версии `v0.0.1` и проверяет SHA256 архива
по файлу контрольных сумм релиза. При первом запуске нужен доступ к GitHub.
`signoz-migrate` создаёт и обновляет схему, затем завершается. На первом запуске
это может занять несколько минут: дождитесь его успешного завершения.
Не обновляйте образы без проверки совместимости схем и резервной копии томов.

Интерфейс: <http://signoz.test/> через существующий Traefik.
Добавьте домен в локальное разрешение имён, как для `grafana.test`.
Домен можно изменить через `SIGNOZ_DOMAIN`. При первом входе создайте учётную запись.
Порты ClickHouse, Keeper и приёма OTLP не публикуются на хост. Их доступность
ограничена сетями Docker; не открывайте их наружу без аутентификации и TLS.

Проверки:

```sh
docker compose ps -a signoz-init signoz-clickhouse signoz-migrate signoz-collector signoz
docker compose logs --tail=100 signoz-migrate signoz-collector signoz
```

## Одинаковые входные данные

Основной Collector загружает конфиги в порядке:

1. `docker/otel-collector/config.yaml` — общий приём и обработка;
2. `docker/otel-collector/local.yaml` — Tempo, Prometheus, Loki;
3. `docker/otel-collector/signoz.yaml` — добавление копии трейсов и метрик в SigNoz.

Последний конфиг заменяет списки экспортёров, сохраняя обе системы:

```text
                        ┌→ Tempo
Приложения → Collector ─┼→ Prometheus (сбор метрик)
                        ├→ Loki (только логи)
                        └→ SigNoz Collector → ClickHouse SigNoz
```

В SigNoz поступают OTLP-метрики приложений и метрики коннектора `spanmetrics`.
Метрики связей, которые сам Tempo отправляет в Prometheus, этим путём не копируются.
Sampling не добавлен: обе системы получают одинаковые входящие трейсы.
Уже сохранённые в Tempo трейсы и история Prometheus в SigNoz не переносятся.
Генерируйте новый трафик и выбирайте одинаковые временные диапазоны для сравнения.
Для APM-метрик подождите несколько циклов сбора (интервал — 30 секунд).

## Ресурсы и хранение

| Компонент | Лимит памяти | Лимит CPU |
|---|---:|---:|
| ClickHouse со встроенным Keeper | 1536 MiB | 1 |
| SigNoz, интерфейс и API | 384 MiB | 0.5 |
| SigNoz Collector | 256 MiB | 0.5 |
| Мигратор, только на запуске | 512 MiB | 0.5 |
| Загрузка UDF, только на первом запуске | 128 MiB | 0.25 |

Сумма лимитов постоянно работающих компонентов — **2176 MiB (2.125 GiB)**,
не включая уже работающий стек Grafana, приложения и основной Collector.
Это ограниченный тестовый бюджет, не заявленный производителем минимум
и не гарантия отсутствия OOM при тяжёлых запросах. Официальная инструкция
рекомендует выделять Docker не менее 4 GB для установки SigNoz.
Первичная миграция может требовать больше ресурсов, чем обычный приём данных.

Конфигурация стенда сама по себе не подтверждает миграции, доставку метрик user-login
или корректность Histogram и SLI в SigNoz. Recording rules Prometheus в SigNoz
не переносятся автоматически. Результаты отдельных экспериментов с другой
конфигурацией не заменяют проверку текущего pipeline.

**Retention SigNoz управляется самим SigNoz, а не конфигами Tempo/Loki.**
После первого входа откройте Settings → Workspace → Retention Controls
(в некоторых версиях — Settings → General) и установите небольшой срок
для трейсов и метрик, например 1 день, если интерфейс допускает это значение.
До изменения действуют стандартные сроки SigNoz, а не наши 24 часа Tempo/Loki.
Лимита размера диска нет: следите за объёмом тома ClickHouse.

Лимиты ClickHouse оставляют возможность фоновых слияний и сброса тяжёлых
сортировок/группировок на диск; служебные журнальные таблицы отключены.
Долгий retention, высокая кардинальность, большой поток и широкие запросы
потребуют увеличения ресурсов. Это не отказоустойчивое продакшен-развёртывание.

## Как выключить сравнение

Не оставляйте активным экспортёр на остановленный SigNoz:

1. Уберите третий `--config=/etc/otelcol-contrib/signoz.yaml` из `command`
   и `healthcheck.test` сервиса `otel-collector` в основном Compose.
   Уберите также его `depends_on: signoz-collector`, иначе Compose снова запустит получатель.
2. Пересоздайте основной Collector: `docker compose up -d otel-collector`.
3. Остановите стенд: `docker compose stop signoz signoz-collector signoz-clickhouse`.

Для полного отключения можно также убрать соответствующий bind mount
и `include: docker-compose.signoz.yml` из основного Compose. Тома не удаляйте,
если хотите сохранить результаты сравнения.

Все конфиги включены в репозиторий. Общие требования к сети, registry, доменам
и порядку остановки — в [инструкции локального стека](../otel-collector/README.md).
